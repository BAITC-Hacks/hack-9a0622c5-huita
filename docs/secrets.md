# Данные и ключи вне Git

В репозиторий попадают код, тесты и публичная документация. CSV организаторов,
загруженные пользователем наборы, отчёты, архивы, приватные заметки и ключи
остаются на машине разработчика или сервера. `organizer/` содержит только код
и руководство; CSV хранятся в `BEESMART_DATA_DIR`, а загрузки и результаты —
в `BEESMART_STORAGE_DIR` (по умолчанию `work/`). `.gitignore` запрещает эти пути;
защита Git дополнительно проверяет содержимое индекса и историю отправляемых
коммитов. Принудительное добавление файла через Git не обходит проверку.

Установите хуки после клонирования:

```bash
python3 scripts/install_hooks.py
```

Проверки не требуют сторонних Python-библиотек:

```bash
python3 scripts/check_repository.py --staged
python3 scripts/check_repository.py --all
python3 scripts/check_repository.py --history
python3 scripts/check_repository.py --history origin/main..HEAD
```

`--staged` проверяет весь будущий снимок индекса, включая неизменённые файлы.
`--all` дополнительно проверяет текущие версии отслеживаемых файлов.
`--history` читает деревья каждого коммита, поэтому обнаруживает также данные,
которые добавили, а затем удалили до отправки. При первой отправке ветки
проверяется вся её достижимая история; при обновлении — новые коммиты.
Неотслеживаемые локальные данные не читаются этими проверками.

Ключи задаются через окружение или локальный `.env`. Разрешённый `.env.example`
содержит только пустые значения или явные заглушки для секретных переменных.
`policies/frozen_policy.json` и публичная схема `open.json` разрешены, но также проверяются
на ключи. Приватные OpenAI-политики и журнал расходов находятся в `<storage>/llm/`
и в Git не входят. Хуки не выводят содержимое совпадений: только путь и тип проблемы.

Проверка отклоняет файлы данных, базы, ключи, архивы, документные выгрузки,
символические ссылки, подмодули и файлы свыше 10 МиБ. В тестах значения для
проверки детектора собираются из отдельных строк внутри временных репозиториев;
настоящие ключи в тестах не используются.

Если секрет уже был отправлен, его нужно отозвать у провайдера. Удаление файла
из последнего коммита не удаляет его из истории. Очистка истории и повторная
публикация выполняются отдельно; хуки ничего не переписывают автоматически.

## После очистки истории

Напарник сначала сохраняет свои несохранённые HTML/CSS/JS-файлы отдельно, затем
клонирует репозиторий в новую папку и переносит только исходники frontend.
Не объединяйте старую историю с очищенной: это может вернуть удалённые CSV.
В новом клоне снова выполните `python3 scripts/install_hooks.py`.

```bash
git clone https://github.com/BAITC-Hacks/hack-9a0622c5-huita.git beesmart-clean
cd beesmart-clean
python3 scripts/install_hooks.py
```

Переписывание веток не удаляет чужие клоны, форки и кешированные старые коммиты.
При необходимости очистки серверных кешей обращаются в GitHub Support; поддержка
самостоятельно определяет, относится ли материал к чувствительным данным.
[Инструкция GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

Локальные hooks можно отключить, а сканирование по сигнатурам не распознаёт любые
произвольные секреты или данные, вставленные в код. Поэтому не обходите проверки,
не добавляйте ключи в исходники и проверяйте diff. CI срабатывает после попадания
коммита на GitHub и не заменяет предварительную проверку на машине разработчика.

## Два разных секрета

- `BEESMART_API_TOKEN` — доступ доверенной команды к API BeeSmart. В браузере он хранится только в памяти страницы.
- `OPENAI_API_KEY` — серверный ключ провайдера. Он используется при подготовке политики и не передаётся frontend или worker.

Корневой `open.json` и маршруты `/openapi.json`, `/open.json` публичны: это схемы,
а не отчёты. Сохранённые отчёты и выгрузки API в production требуют авторизации.
CLI выдаёт путь к приватному отчёту; сам отчёт может содержать названия тарифов,
сегменты и результаты расчёта, поэтому не публикуйте его вместе с исходниками.

`store=false` в запросе OpenAI не включает Zero Data Retention. Модель получает
агрегаты без ID и исходных текстовых названий; условия хранения провайдера описаны
в [руководстве агента](agent.md#что-получает-модель).
