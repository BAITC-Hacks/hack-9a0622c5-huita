# Агент BeeSmart: OpenAI и локальные пилоты

В режиме `openai` модель **GPT-6 Luna** выбирает порядок проверки тарифных гипотез.
После проверки ответа Python-агент проводит пилоты, обновляет оценки и собирает
финальные кампании. `Agent.act(env)` продолжает работать без сети: подготовленная
политика передаётся ему файлом до запуска отдельного процесса оценки.

Модель вызывается через OpenAI Responses API с `reasoning.effort=medium`, строгой
JSON-схемой, `max_output_tokens=4096` и `store=false`. Модель зафиксирована в настройках
для предсказуемого ограничения расходов. Brev/NVIDIA в этом пути не используется;
его бюджет $50 учитывается отдельно. Исторические эффекты задают только приоритет
проверок, а результат локального mock-прогона не предсказывает скрытый балл судейства.

## Настройка

Создайте конфигурацию и откройте её в редакторе:

```bash
python scripts/setup_env.py
nano .env
```

| Переменная | Значение и назначение |
|---|---|
| `BEESMART_AGENT_PROVIDER` | `openai` — подготовка гипотез моделью; `local` — локальная политика без API |
| `OPENAI_API_KEY` | Приватный ключ OpenAI только на сервере |
| `BEESMART_OPENAI_MODEL` | `gpt-6-luna`; остальные модели сейчас не поддерживаются |
| `BEESMART_LLM_BUDGET_USD` | Лимит приложения, по умолчанию `5`, допустимо от `0` до `50` |
| `BEESMART_STORAGE_DIR` | Постоянный приватный каталог отчётов, политик и журнала расходов |
| `BEESMART_DATA_DIR` | Необязательный приватный каталог исходных CSV для `/api/runs` |

Новый `.env` копирует `.env.example`, где выбран `openai` и ключ оставлен пустым.
`setup_env.py` сохраняет существующий `.env` без изменений: для уже настроенного
проекта добавьте эти переменные вручную. При отсутствии переменной provider код
выбирает `local` для совместимости. Затем перезапустите `python -m beesmart`.

Реальный ключ OpenAI не входит в репозиторий и в ходе реализации не предоставлялся.
Интеграционные тесты используют подставной HTTP-транспорт; доступ аккаунта к модели
и реальный платный запрос нужно проверить после настройки ключа. Без ключа выбранный
режим `openai` показывает `needs_configuration`, а запуск получает HTTP 503.

Проверьте конфигурацию через `GET /api/agent`. В production нужен токен доступа
BeeSmart, описанный в [руководстве по развёртыванию](deployment.md). Ключ OpenAI
не передаётся браузеру, worker, URL или логам. Это отдельный секрет от токена BeeSmart.

## Что получает модель

Backend читает только нужные колонки трёх CSV. Для ячеек «текущий тариф × ARPU-класс»
с минимум 10 абонентами он подбирает до трёх целевых тарифов по историческому рангу.
Отбирается максимум 90 гипотез с сохранением доступных LOW, MID и HIGH. В запрос
входят размеры групп, суммарный и средний ARPU, число наблюдений, агрегированный
относительный эффект и цены тарифов. При отсутствии наблюдений историческая
поддержка кандидата равна нулю.

Названия тарифов заменяются на `TNN`, гипотезы — на `hNNN`. Исходные ID абонентов,
строки CSV, описания и другие свободные текстовые поля модели не отправляются.
Таблица соответствия псевдонимов остаётся на сервере. Ответ должен содержать
1–14 разных известных гипотез и покрывать каждый доступный ARPU-класс; это
проверяется заново на сервере. Краткое обоснование на русском ограничено 1000
символами и считается недоверенным текстом: frontend выводит его через `textContent`.

Запрос направляется только на `https://api.openai.com/v1/responses`; внешние proxy
из окружения и перенаправления отключены. Полное тело запроса ограничено 64 КиБ,
ответ — 256 КиБ, ожидание — 45 секундами. Автоматических повторов нет.
Формат ответа соответствует [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

`store=false` отключает обычное сохранение ответа как состояния Responses API,
но **не включает Zero Data Retention**. Политики мониторинга злоупотреблений и
кэширования провайдера действуют отдельно; специальные настройки хранения
оформляются для организации/проекта OpenAI. См. [официальные правила хранения](https://developers.openai.com/api/docs/guides/your-data).

## Кэш и расходы

Проверенные политики сохраняются в `<storage>/llm/policies`, максимум 128 записей.
Ключ кэша учитывает агрегаты, локальную таблицу соответствия тарифов, модель и версию
промпта. Seed и ID загрузки не входят в ключ: повторный запуск тех же данных может
использовать политику без нового платного запроса. При изменении исходных названий
тарифов совпадение одних числовых агрегатов не приводит к выдаче чужой политики.

Перед каждым обращением приложение атомарно записывает резерв **$0.02** в
`<storage>/llm/spend.json`. Новый вызов возможен, если сумма учтённых расходов,
резервов и нового резерва не превышает лимит. По умолчанию приложению выделено
$5 из доступного бюджета OpenAI $50. Другие приложения и баланс аккаунта этим
журналом не отслеживаются.

После корректного ответа резерв заменяется консервативной оценкой по фактическому
числу входных и выходных токенов. Это оценка BeeSmart, а не счёт OpenAI. При таймауте,
неполном/некорректном ответе или другой неуспешной попытке резерв остаётся, поскольку
факт расходов может быть неизвестен. Не удаляйте журнал для обнуления лимита.
Повреждённый журнал блокирует новые обращения; сохранённые политики и отчёты
должны храниться на постоянном приватном томе вместе с ним.

При ошибке OpenAI запуск получает `failed` и понятное сообщение. Автоматического
переключения на другой провайдер или локальную стратегию нет. Для намеренной
работы без API задайте `BEESMART_AGENT_PROVIDER=local` и перезапустите сервер.

## Тестовый запуск через API

Из локального каталога пакета организаторов отправьте три CSV:

```bash
curl http://127.0.0.1:8000/api/uploads/run \
  -H 'X-BeeSmart-Request: 1' \
  -F 'profile=@customer_profile.csv' \
  -F 'history=@data/change_tariff.csv' \
  -F 'tariffs=@data/dict_tariff.csv' \
  -F 'seed=42'
```

Ответ 202 содержит `id`. Опрос `GET /api/runs/{id}` показывает подготовку политики,
затем пилоты и финальные метрики. `run.llm.cache_hit=true` означает повторное
использование политики; токены и стоимость текущего обращения в этом случае
нулевые. Данные результата и экспорты описаны в [контракте API](api.md).

Для проверки кода без ключа и без платных запросов выполните:

```bash
python -m pytest tests/test_llm.py tests/test_llm_security.py -q
```

## Ошибки планирования

HTTP-ошибка до старта содержит `detail`. После ответа 202 ошибка появляется в
`run.error`, а код — в `run.llm.error_code`.

| Код | Действие |
|---|---|
| `missing_api_key`, `missing_key` | Настроить серверный `OPENAI_API_KEY` и перезапустить |
| `authentication_failed` | Проверить действительность ключа OpenAI |
| `access_denied`, `model_unavailable` | Проверить разрешения проекта и доступ к GPT-6 Luna |
| `rate_limited` | Проверить квоту, частоту запросов и оплату OpenAI |
| `provider_unavailable`, `provider_error` | Проверить доступность провайдера и настройки; повтор только вручную |
| `timeout`, `network_error` | Проверить сеть; учесть сохранённый резерв до повторного запуска |
| `invalid_context`, `no_candidates`, `context_too_large` | Проверить CSV и доступные ячейки для пилотов |
| `refused`, `incomplete_response`, `invalid_response`, `invalid_policy`, `missing_coverage` | Ответ не принят; расчёт остановлен |
| `missing_usage`, `usage_invalid`, `response_too_large` | Ответ не прошёл ограничения или проверку учёта |
| `unsupported_model` | Использовать `gpt-6-luna` |
| `budget_exhausted` | Проверить лимит приложения и зарезервированные расходы |
| `budget_storage` | Восстановить доступ к приватному журналу расходов без обнуления |
| `interrupted` | Запуск был прерван; проверить состояние сервера перед повтором |

## Экспорт для хакатона

Официальные `local_eval.py` и `make_submission.py` запускают `Agent()` с корневой
`frozen_policy.json`. Она содержит базовую стратегию; API с OpenAI использует другую
приватную политику. Для совпадения результатов нужен тот же файл политики и seed 42.

После готового API-запуска с seed 42 выполните:

```bash
python scripts/build_submission.py --run <UUID>
```

По умолчанию результат помещается в `<storage>/submissions/<UUID>`. Экспортёр находит
точный SHA-256 политики из отчёта, копирует код и три локальных CSV, запускает
неизменённый `make_submission.py` без API-ключей и сравнивает все семь колонок CSV
и порядок кампаний с исходным отчётом. При несовпадении, отсутствии политики,
незавершённом запуске или другом seed экспорт прекращается. Существующая папка
никогда не перезаписывается. Ключи, `.env` и остальные данные проекта не копируются.

Опции: `--storage-dir` для другого хранилища запусков, `--data-dir` для восстановленного
набора CSV и `--output` для нового приватного каталога. Это полезно, если загрузка
уже вышла из пяти сохраняемых наборов. Политика также должна оставаться в кеше.
Внутри репозитория результат разрешён только в `work/`; экспорт не добавляется в Git.

В папке находятся `agent.py`, пакет `beesmart/core` с `__init__.py`, точная
`frozen_policy.json`, `requirements.txt`, `submission.csv` и manifest с хешами.
Официальные скрипты и три CSV сохранены для локального воспроизведения; исходные CSV
не нужно добавлять в Git или отправлять как код решения. Следуйте актуальным правилам
организаторов о составе сдачи. Воспроизведение подтверждает совпадение локального
плана, а не будущий балл скрытой среды.
