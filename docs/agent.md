# Агент BeeSmart: OpenAI и локальные пилоты

В режиме `openai` модель **GPT-6 Luna** выбирает порядок проверки тарифных гипотез.
После проверки ответа Python-агент адаптивно проводит пилоты, обновляет оценки,
решает, нужна ли дополнительная проверка, и собирает финальные кампании. `Agent.act(env)` продолжает работать без сети: подготовленная
политика передаётся ему файлом до запуска отдельного процесса оценки.

Некэшированная подготовка делает один запрос модели. Итеративного LLM tool calling
в реализации нет: пилотами и повторным выбором плана управляет Python. Режим `local`
читает `policies/frozen_policy.json`. API и самостоятельный CLI используют общий
процесс расчёта в `beesmart/application/`; HTTP находится отдельно в `beesmart/api/`.
[Архитектура, каталоги и схема потока](architecture.md).

По [условиям кейса](../organizer/PARTICIPANT_GUIDE.md) LLM опционален: «LLM в контуре
принятия решений — разрешено и приветствуется». Обязательная агентная логика —
самостоятельный выбор пилотов и изменение решений по наблюдаемому результату.
Она реализована в обоих режимах; эффект гипотез подтверждается пилотами.

Модель вызывается через OpenAI Responses API с `reasoning.effort=medium`, строгой
JSON-схемой, `max_output_tokens=4096` и `store=false`. Модель зафиксирована в настройках
для предсказуемого ограничения расходов. Brev/NVIDIA в этом пути не используется;
его бюджет $50 учитывается отдельно. Исторические эффекты задают только приоритет
проверок, а результат локального mock-прогона не предсказывает скрытый балл судейства.

## Настройка

Создайте конфигурацию и откройте её в редакторе:

```bash
python scripts/setup_env.py
nano .env
```

| Переменная | Значение и назначение |
|---|---|
| `BEESMART_AGENT_PROVIDER` | `openai` — подготовка гипотез моделью; `local` — локальная политика без API |
| `OPENAI_API_KEY` | Приватный ключ OpenAI только на сервере |
| `BEESMART_OPENAI_MODEL` | `gpt-6-luna`; остальные модели сейчас не поддерживаются |
| `BEESMART_LLM_BUDGET_USD` | Лимит приложения, по умолчанию `5`, допустимо от `0` до `50` |
| `BEESMART_STORAGE_DIR` | Постоянный приватный каталог отчётов, политик и журнала расходов |
| `BEESMART_DATA_DIR` | Необязательный приватный каталог исходных CSV для `/api/runs` |

Новый `.env` копирует `.env.example`, где выбран `openai` и ключ оставлен пустым.
`setup_env.py` сохраняет существующий `.env` без изменений: для уже настроенного
проекта добавьте эти переменные вручную. При отсутствии переменной provider код
выбирает `local` для совместимости. Затем перезапустите `python -m beesmart`.

Ключ OpenAI не входит в репозиторий. Автоматические тесты используют подставной
HTTP-транспорт. **23 сентября 2026 года** отдельно проверен один реальный запрос
GPT-6 Luna без попадания в кэш: на 270 вымышленных профилях модель выбрала 6 гипотез,
все 6 были проверены пилотами, итоговый план из одной кампании прошёл ограничения.
Провайдер сообщил 853 входных и 321 выходной токен; локальная оценка расхода —
$0.000268. Это подтверждение работы интеграции, а не баланса аккаунта или качества
кампаний на другой аудитории. Отчёт проверки хранится приватно. Без ключа выбранный
режим `openai` показывает `needs_configuration`, а запуск получает HTTP 503.

Проверьте конфигурацию через `GET /api/agent`. В production нужен токен доступа
BeeSmart, описанный в [руководстве по развёртыванию](deployment.md). Ключ OpenAI
не передаётся браузеру, worker, URL или логам. Это отдельный секрет от токена BeeSmart.

## Что получает модель

Backend читает только нужные колонки трёх CSV. Для ячеек «текущий тариф × ARPU-класс»
с минимум 10 абонентами он подбирает до трёх целевых тарифов по историческому рангу.
Отбирается максимум 90 гипотез с сохранением доступных LOW, MID и HIGH. В запрос
входят размеры групп, суммарный и средний ARPU, число наблюдений, агрегированный
относительный эффект и цены тарифов. При отсутствии наблюдений историческая
поддержка кандидата равна нулю.

Названия тарифов заменяются на `TNN`, гипотезы — на `hNNN`. Исходные ID абонентов,
строки CSV, описания и другие свободные текстовые поля модели не отправляются.
Таблица соответствия псевдонимов остаётся на сервере. Ответ должен содержать
1–14 разных известных гипотез и покрывать каждый доступный ARPU-класс; это
проверяется заново на сервере. Краткое обоснование на русском ограничено 1000
символами и считается недоверенным текстом: frontend выводит его через `textContent`.

Запрос направляется только на `https://api.openai.com/v1/responses`; внешние proxy
из окружения и перенаправления отключены. Полное тело запроса ограничено 64 КиБ,
ответ — 256 КиБ, ожидание — 45 секундами. Автоматических повторов нет.
Формат ответа соответствует [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

`store=false` отключает обычное сохранение ответа как состояния Responses API,
но **не включает Zero Data Retention**. Политики мониторинга злоупотреблений и
кэширования провайдера действуют отдельно; специальные настройки хранения
оформляются для организации/проекта OpenAI. См. [официальные правила хранения](https://developers.openai.com/api/docs/guides/your-data).

## Кэш и расходы

Проверенные политики сохраняются в `<storage>/llm/policies`, максимум 128 записей.
Ключ кэша учитывает агрегаты, локальную таблицу соответствия тарифов, модель и версию
промпта. Seed и ID загрузки не входят в ключ: повторный запуск тех же данных может
использовать политику без нового платного запроса. При изменении исходных названий
тарифов совпадение одних числовых агрегатов не приводит к выдаче чужой политики.

Перед каждым обращением приложение атомарно записывает резерв **$0.02** в
`<storage>/llm/spend.json`. Новый вызов возможен, если сумма учтённых расходов,
резервов и нового резерва не превышает лимит. По умолчанию приложению выделено
$5 из доступного бюджета OpenAI $50. Другие приложения и баланс аккаунта этим
журналом не отслеживаются.

После корректного ответа резерв заменяется консервативной оценкой по фактическому
числу входных и выходных токенов. Это оценка BeeSmart, а не счёт OpenAI. При таймауте,
неполном/некорректном ответе или другой неуспешной попытке резерв остаётся, поскольку
факт расходов может быть неизвестен. Не удаляйте журнал для обнуления лимита.
Повреждённый журнал блокирует новые обращения; сохранённые политики и отчёты
должны храниться на постоянном приватном томе вместе с ним.

Лимит LLM-расходов отличается от бюджета 100 000 у.е. на контакты. Если на новый
запрос не хватает LLM-бюджета, уже принятый расчёт продолжается с локальной политикой
без нового обращения к OpenAI. Готовая политика в кеше может использоваться без
платного запроса. Для намеренной работы без API выберите `BEESMART_AGENT_PROVIDER=local`.

## Ошибки и запасная логика

Проверки до старта и ошибки принятого запуска обрабатываются по-разному:

- **До старта:** отсутствующий ключ (`needs_configuration`) или недоступный/
  повреждённый журнал расходов (`storage_error`) блокируют запуск; API возвращает
  HTTP 503 до ответа 202. Исправьте настройку или явно выберите `local`.
- **После принятия запуска:** обработанная ошибка подготовки политики (`LLMError`)
  или таймаут включает локальную резервную стратегию. Сюда относятся ошибки OpenAI,
  отклонённый ответ, `budget_exhausted` и ошибка сохранения политики `policy_storage`.
  Worker проводит пилоты и оценивает план в оставшееся время. Повторного платного
  запроса и перехода на другого внешнего провайдера нет.
- **Отмена/остановка процесса:** расчёт прекращается; резервная стратегия не запускается.

Переход виден в событии `agent_fallback`. В `run.llm` сохраняются `provider`, `model`,
`status="failed"`, исходный `error_code`, `fallback_used=true` и объяснение
`fallback_reason`. Общий `run.status` может завершиться `completed`, а `run.error`
остаться `null`. Не определяйте успешность всего расчёта только по `run.llm.status`.
Экономическая оценка находится отдельно в `run.metrics.status` (`PASS`/`FAIL`).

Используется `policies/frozen_policy.json`; при отсутствии или повреждении этого
артефакта ядро имеет встроенную детерминированную очередь. Уже учтённые расходы,
токены и резерв не обнуляются: провайдер мог обработать запрос до ошибки.
Экспорт проверяет хеш фактически применённой политики и не подменяет её другой.

Общий лимит API и CLI по умолчанию — 540 секунд. Подготовка политики ограничена
меньшим из 50 секунд и 20% общего срока; worker получает остаток. Настройка срока
задаётся программно, отдельной переменной окружения нет. Отмена ожидает завершения
начатой файловой транзакции, чтобы не повредить учёт; это не гарантия прерывания
зависшего системного ввода-вывода. Если общий срок уже истёк, worker не запускается.

## Самостоятельный запуск без HTTP

Из корня проекта, после установки зависимостей:

```bash
python -m beesmart.application --data-dir '/path/package' --provider local --seed 42
```

Для подготовки гипотез моделью укажите `--provider openai`. CLI читает те же `.env`
и настройки, что API. Неуказанные `--data-dir`, `--storage-dir` и `--provider` берутся
из настроек. `--seed` принимает целое от 0 до 4294967295, по умолчанию 42.

На stdout выводится JSON-сводка: `id`, `status`, `seed`, `provider`, `model`,
`llm_status`, `cache_hit`, `fallback_used`, `fallback_reason`, `pilots`, `campaigns`,
`net_arpu_gain`, `error`, `report`.
`report` — путь к приватному сохранённому отчёту. Коды выхода: `0` — расчёт завершён,
`1` — запуск завершился с ошибкой, `2` — ошибка настройки, данных или хранилища.
Код `0` возможен при `llm_status="failed"`, если локальная стратегия завершила
расчёт; признак этого перехода — `fallback_used=true`.

Остановите веб-сервер перед CLI с тем же хранилищем: блокировка действует на весь
срок работы процесса. Для независимого локального теста можно добавить
`--storage-dir work/cli-local`. OpenAI лучше запускать с общим существующим
хранилищем после остановки сервера: отдельный каталог имеет отдельный журнал и
лимит, а фактический расход аккаунта остаётся общим.

## Тестовый запуск через API

Из локального каталога пакета организаторов отправьте три CSV:

```bash
curl http://127.0.0.1:8000/api/uploads/run \
  -H 'X-BeeSmart-Request: 1' \
  -F 'profile=@customer_profile.csv' \
  -F 'history=@data/change_tariff.csv' \
  -F 'tariffs=@data/dict_tariff.csv' \
  -F 'seed=42'
```

Ответ 202 содержит `id`. Опрос `GET /api/runs/{id}` показывает подготовку политики,
затем пилоты и финальные метрики. `run.llm.cache_hit=true` означает повторное
использование политики; токены и стоимость текущего обращения в этом случае
нулевые. Данные результата и экспорты описаны в [контракте API](api.md).

Для проверки кода без ключа и без платных запросов выполните:

```bash
python -m pytest tests/test_llm.py tests/test_llm_security.py -q
```

## Ошибки планирования

HTTP-ошибка до старта содержит `detail`. Для принятого запуска причина перехода
на резервную стратегию находится в `run.llm.fallback_reason`, код — в
`run.llm.error_code`. `run.error` описывает ошибку всего расчёта или предупреждение
о сохранении результата; при успешном завершении с резервной стратегией оно
может оставаться `null`.

| Код | Действие |
|---|---|
| `missing_api_key`, `missing_key` | Настроить серверный `OPENAI_API_KEY` и перезапустить |
| `authentication_failed` | Проверить действительность ключа OpenAI |
| `access_denied`, `model_unavailable` | Проверить разрешения проекта и доступ к GPT-6 Luna |
| `rate_limited` | Проверить квоту, частоту запросов и оплату OpenAI |
| `provider_unavailable`, `provider_error` | Проверить доступность провайдера и настройки; повтор только вручную |
| `timeout`, `network_error` | Проверить сеть; учесть сохранённый резерв до повторного запуска |
| `planning_timeout` | Истёк срок подготовки гипотез; принятый расчёт продолжает локальная стратегия |
| `invalid_context`, `no_candidates`, `context_too_large` | Проверить CSV и доступные ячейки для пилотов |
| `refused`, `incomplete_response`, `invalid_response`, `invalid_policy`, `missing_coverage` | Ответ модели не принят; проверить причину перехода на локальную стратегию |
| `missing_usage`, `usage_invalid`, `response_too_large` | Ответ не прошёл ограничения или проверку учёта |
| `unsupported_model` | Использовать `gpt-6-luna` |
| `budget_exhausted` | Новый платный запрос не выполнен; принятый расчёт продолжает локальная стратегия |
| `budget_storage` | Восстановить доступ к приватному журналу расходов без обнуления |
| `policy_storage` | Проверить запись приватной политики; учтённая стоимость ответа сохранена, расчёт продолжается локально |
| `interrupted` | Запуск был прерван; проверить состояние сервера перед повтором |

## Экспорт для хакатона

Базовый `Agent()` использует `policies/frozen_policy.json`. OpenAI-запуск сохраняет
свою приватную политику. Для совпадения результатов нужны точная политика,
исходные данные, код и seed 42. Официальный генератор находится в `organizer/`;
экспортёр сам подготавливает нужные пути импорта и рабочий каталог.

После завершённого API- или CLI-запуска с seed 42 скопируйте `id` из отчёта и выполните:

```bash
RUN_ID='вставьте-id-завершённого-запуска'
python scripts/build_submission.py --run "$RUN_ID"
```

По умолчанию результат помещается в `<storage>/submissions/<UUID>`. Экспортёр находит
точный SHA-256 политики из отчёта, копирует код и три локальных CSV, запускает
неизменённый `make_submission.py` без API-ключей и сравнивает все семь колонок CSV
и порядок кампаний с исходным отчётом. При несовпадении, отсутствии политики,
незавершённом запуске или другом seed экспорт прекращается. Существующая папка
никогда не перезаписывается. Ключи, `.env` и остальные данные проекта не копируются.

Опции: `--storage-dir` для другого хранилища запусков, `--data-dir` для исходного
набора CSV и `--output` для нового приватного каталога. Если CLI был запущен с
путями, отличающимися от `.env`, передайте экспортёру те же пути:

```bash
python scripts/build_submission.py --run "$RUN_ID" \
  --storage-dir work/cli-local --data-dir '/path/package'
```

Явный путь к данным также позволяет использовать восстановленный набор. Это полезно, если загрузка
уже вышла из пяти сохраняемых наборов. Политика также должна оставаться в кеше.
Внутри репозитория результат разрешён только в `work/`; экспорт не добавляется в Git.

В папке находятся `agent.py`, необходимое офлайн-ядро `beesmart/agent/`, точная
политика, `requirements.txt`, `submission.csv` и manifest с хешами. Импорт адаптера
не требует FastAPI, HTTP-клиента OpenAI или ключей. Официальные скрипты и три CSV
сохранены для локального воспроизведения; исходные CSV не нужно добавлять в Git
или отправлять как код решения. Следуйте актуальным правилам
организаторов о составе сдачи. Воспроизведение подтверждает совпадение локального
плана, а не будущий балл скрытой среды.

Нужны оба файла пакетов: `beesmart/__init__.py` и `beesmart/agent/__init__.py`.
Полная минимальная структура перечислена в [README](../README.md#экспорт-для-хакатона).
`submission.csv` обязателен по кейсу, хотя CSV не допускаются в Git проекта.
Официальные `local_eval.py` и `make_submission.py` запускайте из каталога экспорта,
где сохранены их плоские импорты и относительные пути к данным. В основном проекте
используйте `python -m beesmart.application`.
