# BeeSmart — backend тарифных кампаний

FastAPI + Python 3.12. ООП-ядро `Agent.act(env)` работает и через API,
и через оригинальные проверочные скрипты организаторов.
Контракт для frontend-разработчика: [api.md](api.md).
Frontend подключается как `static/index.html` + CSS/JavaScript, без Node.js.

## Локальный запуск

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m beesmart
```

Адрес backend: http://127.0.0.1:8000. Проверка: `/api/health`.
Необходимые CSV включены: `customer_profile.csv`, `data/change_tariff.csv`,
`data/dict_tariff.csv`. Это оригинальные **синтетические** данные организаторов:
23 441 абонент, 21 тариф. Исходные файлы среды сохранены без изменений.

```bash
curl -X POST http://127.0.0.1:8000/api/runs \
  -H 'Content-Type: application/json' \
  -H 'X-BeeSmart-Request: 1' \
  -d '{"seed":42}'
curl http://127.0.0.1:8000/api/runs/latest
```

### Запуск на загруженных CSV

Фронтенд отправляет файлы одним multipart-запросом; агент стартует автоматически.
Из корня проекта можно проверить тот же сценарий:

```bash
curl http://127.0.0.1:8000/api/uploads/run \
  -H 'X-BeeSmart-Request: 1' \
  -F 'profile=@customer_profile.csv' \
  -F 'history=@data/change_tariff.csv' \
  -F 'tariffs=@data/dict_tariff.csv' \
  -F 'seed=42'
```

Получите статус по `/api/runs/{id}`. Ответ содержит источник данных в `dataset`,
после `completed` — кампании, метрики и ссылки для скачивания через ID запуска.
Каждая загрузка проходит проверку и хранится отдельно в `work/datasets`;
сохраняются последние 5 наборов. Контракт и пример `fetch` — в [api.md](api.md).

Один расчёт выполняется в отдельном процессе; API остаётся доступным.
Повторный запуск во время активного расчёта получает 409. JSON-отчёты сохраняются
в `work/runs` (последние 20); кампании можно скачать через API как `submission.csv`.
API принимает запросы только с локального компьютера. Доступ извне и авторизация
для публичного размещения в эту версию не входят.

## Агент и проверка

```bash
python -m pytest tests -q
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Агент проверяет до 14 гипотез с попыткой охватить LOW/MID/HIGH. Затем уточняет
пограничные результаты, если ожидаемая польза покрывает расходы. Оценки пилотов
учитывают шум и канал; для звонков применяется поправка на насыщение конверсии.
Финальные сегменты проверяются на пересечения и полное соответствие лимитам.
Три детерминированные жадные сборки выбирают план по осторожной оценке дохода.
Эта эвристика не гарантирует глобальный оптимум или положительный скрытый балл.

В локальном прогоне seed 42: PASS, чистый прирост около 1 286 160 у.е.,
14 пилотов и 2 финальные кампании. Мок-среда подтверждает механику,
а эффекты скрытого судейства будут другими.

Структура: `agent.py` — контракт сдачи; `beesmart/core/` — модель данных,
оценки, планировщик и оркестрация; `beesmart/web.py` — маршруты;
`datasets.py` — кеш агрегатов CSV; `runs.py` — выполнение и хранение запусков;
`worker.py` — вызов официального локального оценщика вне API-процесса.

Бюджеты OpenAI и Brev/NVIDIA — по $50 отдельно. Текущая версия использует
детерминированную базовую политику и не выполняет платных LLM-вызовов.
Баланс аккаунтов не проверяется. Ключи не передаются браузеру и процессу расчёта.

Основные требования сверены с `PARTICIPANT_GUIDE.md` и фактическим API среды.
Данные организаторов содержат 5 пустых ARPU-сегментов и 110 пустых data-сегментов;
агент учитывает реальный состав фильтров и не подменяет категории.
