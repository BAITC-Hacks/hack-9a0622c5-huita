# BeeSmart — агент тарифных кампаний

BeeSmart — проект для кейса HackAlem AI × Beeline. Агент проверяет гипотезы о смене тарифа на небольшой аудитории, оценивает результаты пилотов и собирает план кампаний с учётом бюджета, охвата и стоимости контактов. Проект включает работающий Python-агент, локальную тестовую среду и FastAPI backend для будущего веб-интерфейса.

> Данные и тарифы синтетические и предоставлены организаторами хакатона. Результаты локальных тестов не предсказывают балл на судействе.

## Что делает агент

Исторические данные о сменах тарифов используются только для определения порядка проверки: они относятся к другой выборке и не показывают истинную реакцию целевых абонентов. Агент проводит платные пилоты через `env.run_pilot`, обновляет оценки эффекта и использует их при выборе финальных кампаний.

В одном запуске агент:

1. Загружает публичный профиль абонентов, тарифы, каналы и локальную политику.
2. Формирует гипотезы по текущему тарифу, ARPU-сегменту и целевому тарифу.
3. Проводит до 14 первых пилотов, стараясь охватить LOW, MID и HIGH; при необходимости уточняет пограничные оценки. Общий лимит — 20 пилотов.
4. Отбрасывает варианты с недостаточной нижней оценкой эффекта, строит аудитории и подбирает каналы.
5. Выбирает целые непересекающиеся кампании в пределах оставшегося бюджета и числа контактов.

В зачётном вызове `Agent.act(env)` нет сетевых обращений к LLM. Решение строится на фактических результатах пилотов и детерминированной логике. Сейчас `frozen_policy.json` содержит пустую базовую политику; подготовителя LLM-политики в репозитории нет.

Лимиты задачи: 100 000 у.е. на контакты, 15 000 контактов, до 20 пилотов и до 10 финальных кампаний. Агент ограничивает собственный поиск мягким таймером, чтобы оставить время на формирование ответа.

## Production, OpenAPI и секреты

Backend поддерживает local/production. В production обязательны HTTPS, Bearer-токен
BeeSmart, точные разрешённые hosts/origins и постоянное хранилище. Один worker и одна
реплика рассчитаны на доверенную команду с общим доступом.

- [OpenAPI: open.json](open.json) — полный контракт запросов и ответов для frontend.
- На работающем сервере схема доступна по `/openapi.json` и `/open.json` без токена.
- [Docker / HTTPS / настройки](docs/deployment.md).
- [Защита Git и действия после очистки истории](docs/secrets.md).

**CSV, загрузки, отчёты и `.env` запрещены в Git.** В чистом клоне данных нет:
они загружаются через API из вашего локального пакета. Тесты создают вымышленные данные.

Агент сейчас работает **на локальном Python-алгоритме, без OpenAI и Brev API**.
`GET /api/agent` показывает используемый движок. Brev — вычислительная инфраструктура;
его наличие не подключает модель автоматически. Расчёт API использует mock-среду,
а Docker-сборка и внешний TLS ещё требуют проверки на целевом сервере.

## Состояние проекта

- Агент и его алгоритмическое ядро реализованы.
- FastAPI backend предоставляет запуск расчётов на встроенных данных или трёх загруженных CSV, просмотр событий и результатов, а также скачивание плана. После проверки загруженных файлов расчёт начинается автоматически.
- `static/` содержит изображения. Готовой страницы `static/index.html` пока нет: веб-интерфейс предстоит сделать и подключить к API.
- README и контракт backend для frontend-разработки дополняют друг друга: [документация backend](docs/backend.md) и [API для фронтенда](docs/api.md).

docs/backend.md             запуск backend и сведения об агенте

Корневой `agent.py` короткий, потому что он подключает `CampaignAgent` из `beesmart/core/runner.py`. Основная логика находится в модулях пакета `beesmart`. `agent_template.py` — отдельный упрощённый пример; он не является реализацией, которую запускает текущий проект.

## Запуск проекта

Требуется Python 3.12. Создайте виртуальное окружение и установите зафиксированные зависимости:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python scripts/setup_env.py
python scripts/install_hooks.py
```

Запустите локальный backend:

```bash
python -m beesmart
```

Сервис будет доступен по адресу <http://127.0.0.1:8000>. Проверка готовности: <http://127.0.0.1:8000/api/health>. Если страницы frontend ещё нет, корневой адрес покажет статус backend и ссылки на overview и схему API.

`setup_env.py` создаёт приватный `.env` с правами `0600` и случайным токеном BeeSmart, не выводя его. Существующий файл не меняется. Откройте `nano .env` для настройки; в репозиторий входит только пустой `.env.example`.

### Проверки агента

```bash
python -m pytest tests -q
python local_eval.py
python local_eval.py --runs 10
```

Для `local_eval.py` и `make_submission.py` предварительно разместите официальный пакет CSV локально в его исходной структуре. Эти данные не входят в клон. `local_eval.py` запускает корневой `agent.py` на mock-среде и считает результат локальным scorer. `--runs 10` показывает разброс по seed. Для создания файла плана выполните:

```bash
python make_submission.py
```

Команда создаёт `submission.csv` в корне репозитория. Этот файл генерируется из mock-прогона с фиксированным seed; результат не обязан совпадать с планом в скрытой среде судейства.

На seed 42 текущий локальный прогон показал PASS и чистый прирост около 1 286 160 у.е. при 14 пилотах и 2 финальных кампаниях. Это пример одного прогона, а не обещание доходности: mock-эффекты отличаются от скрытых эффектов на судействе.

## Backend API

Frontend размещается в `static/` либо на явно разрешённом origin. В production к данным требуется `Authorization: Bearer <токен BeeSmart>`; ключи провайдеров браузеру не передаются. Подробные поля ответов описаны в [docs/api.md](docs/api.md).

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверить, что сервис запущен |
| `GET` | `/api/overview` | Получить описание встроенного набора данных, лимитов и доступных файлов |
| `POST` | `/api/uploads/run` | Загрузить три CSV и автоматически запустить расчёт |
| `POST` | `/api/runs` | Запустить расчёт на встроенных данных, например с `{"seed":42}` |
| `GET` | `/api/runs/latest` | Получить последний запуск |
| `GET` | `/api/runs/{id}` | Получить состояние, события, диагностику и результат |
| `GET` | `/api/runs/{id}/submission.csv` | Скачать итоговые кампании |
| `GET` | `/api/runs/{id}/report.json` | Скачать полный отчёт запуска |
| `GET` | `/api/data/{file_id}` | Скачать разрешённый CSV из overview |
| `GET` | `/openapi.json` / `/open.json` | Получить публичную схему API |
| `GET` | `/api/agent` | Узнать движок агента и тип оценки |

Для всех POST нужен заголовок `X-BeeSmart-Request: 1`. Seed — целое число от 0 до 4294967295, по умолчанию 42. Пример запуска на встроенных данных:

```bash
curl -X POST http://127.0.0.1:8000/api/runs \
  -H 'Content-Type: application/json' \
  -H 'X-BeeSmart-Request: 1' \
  -d '{"seed":42}'
```

### Загрузка CSV и автоматический расчёт

Отправьте три файла в `multipart/form-data`. Пример запускается из приватной локальной папки с CSV организаторов; пути можно заменить своими файлами с той же схемой:

```bash
curl http://127.0.0.1:8000/api/uploads/run \
  -H 'X-BeeSmart-Request: 1' \
  -F 'profile=@customer_profile.csv' \
  -F 'history=@data/change_tariff.csv' \
  -F 'tariffs=@data/dict_tariff.csv' \
  -F 'seed=42'
```

| Поле | Содержимое | Лимит файла | Лимит строк |
|---|---|---|---|
| `profile` | Профиль абонентов с готовой колонкой `predicted_arpu` | 32 МиБ | 100 000 |
| `history` | История смен тарифов | 16 МиБ | 200 000 |
| `tariffs` | Справочник тарифов | 256 КиБ | 100 |

CSV должны быть в UTF-8 с разделителем-запятой и содержать не более 128 колонок. Общий лимит запроса — 50 МиБ, время передачи — 30 секунд. Backend проверяет схему, значения и возможность сформировать допустимые сегменты. Сырые таблицы трафика и помесячного ARPU этот маршрут не преобразует в профиль. Подробные требования и пример загрузки из браузера приведены в [docs/api.md](docs/api.md).

Ответ `202` содержит `id` запуска: файлы прошли проверку и расчёт поставлен в очередь. Отдельно вызывать `/api/runs` после загрузки не нужно. Получайте состояние через `GET /api/runs/{id}` примерно раз в секунду, пока `status` равен `queued` или `running`. При `completed` доступны кампании, метрики и итоговый CSV; при `failed` поле `error` объясняет ошибку. Ошибки самого HTTP-запроса содержат сообщение в `detail`.

У запуска на загруженных файлах поле `dataset` содержит `source: "uploaded"`, идентификатор набора и число абонентов, строк истории и тарифов; у встроенного набора — `source: "bundled"`. `/api/overview` всегда описывает встроенные данные, поэтому для результата загрузки используйте `run.dataset` и `run.metrics.baseline_total_arpu`. Оба режима используют локальную mock-среду; метрики показывают результат симуляции.

Расчёт выполняется в отдельном процессе. Пока идёт загрузка или расчёт, повторный запрос на запуск возвращает `409`. Загруженные наборы сохраняются отдельно в `work/datasets` (последние 5), отчёты — в `work/runs` (последние 20); эти каталоги исключены из Git. Локальный режим ограничен loopback. Production-режим требует авторизацию и HTTPS; каталоги хранения выносятся в постоянный том через BEESMART_STORAGE_DIR. Незавершённые расчёты после перезапуска получают failed и могут быть запущены повторно.

## Ограничения

Пилоты шумные, поиск ограничен числом проверок, а планировщик использует эвристику. Агент не гарантирует положительный результат или глобально оптимальный план. Один seed фиксирует случайность локального прогона, но не скрытую модель эффектов. Перед сдачей сверяйте состав файлов и правила публикации с актуальными требованиями организаторов.
